# Проверка разбора аудио

Этот отчёт разделяет проверку кода, измерения реальных моделей на Linux и
проверку Android. Эмулятор не считается физическим телефоном. Сборка APK
остановлена по отдельному запросу пользователя; готовый APK и проверка
Android-приложения во время выполнения не входят в результат этой работы.

## Проверка приложения и сохранности данных

- TypeScript: `npx tsc --noEmit` — успешно.
- ESLint: `npx eslint . --quiet` — без ошибок.
- Jest: **14 наборов, 110 тестов** — успешно.
- SQLite: `npm run test:sqlite` — успешно на реальной SQLite, включая миграцию
  старых данных и настроек, откат транзакции, дубли, отмену, поздний ответ
  предыдущего задания, прерывание/повтор, сохранение ручных правок,
  конфликт ревизий, резервную копию/восстановление/привязку аудио и удаление.
- Android JVM: **4 проверки правил** — успешно. Они проверяют сигнатуры файлов,
  безопасные пути, границы повтора и замену повреждённой локальной копии.
  Это не проверка MediaPlayer на устройстве.
- Backend: **28 целевых тестов** — успешно, включая контракт, отмену, повторы,
  реальное декодирование, сохранение частичного результата и остановку
  дочернего процесса после принудительного завершения сервера.

Тесты интерфейса проверяют использование фактической позиции проигрывателя,
паузу/перемотку, сохранение ревизии и изменения границ строки. Они используют
управляемый нативный мост, а не доказывают точность MediaPlayer на телефоне.
Гонка отмены импорта с быстрым повтором сначала воспроизведена падающим тестом,
затем устранена: завершённые hash-файлы больше не удаляются из старого callback.

## Полные песни: текст и время слов

Снимок фактических измерений находится в
[jamendo-small-results.json](jamendo-small-results.json). В первом коммите он
содержит **11 завершённых английских записей**; оставшиеся записи выбранного
набора из 20 обрабатываются отдельно. Число строк и поле `summary.recordings`
в JSON определяют фактически завершённый объём, а не целевое число тестов.

Источник: [JamendoLyrics](https://huggingface.co/datasets/jamendolyrics/jamendolyrics)
и [Jam-ALT](https://huggingface.co/datasets/jamendolyrics/jam-alt).
При распознавании используется только аудио. Человеческие тексты Jam-ALT
и временные метки JamendoLyrics подаются только в последующую оценку.
Новая человеческая разметка в этой работе не создавалась.

WER — число замен, удалений и вставок, делённое на число слов эталона.
Маркеры `…` учитываются как ошибки. Средняя ошибка начала/конца слова считается
только для точно совпавших при выравнивании слов; её нельзя распространять
на пропущенные и неправильно распознанные слова. Поэтому рядом сохраняется
число совпадений и количество слов эталона. Человеческих аккордовых эталонов
у этой выборки нет: поле `chordAccuracy` намеренно равно `null`.

Каждая запись прошла настоящий цикл HTTP upload → job → polling → result,
с проверкой SHA-256/ключа задания и очисткой файлов. Измерения выполнены
на общем Linux x86-64 CPU, одновременно с разработкой. `wallSeconds` включает
цикл HTTP; `elapsedSeconds` — обработку worker. Пик RSS включает worker
и его дочерние процессы, но не HTTP-сервер, файловый кеш ОС или GPU VRAM.
Это не производительность Android, Windows-компьютера пользователя или GPU.

## Инструментальные записи: аккорды и отсутствие выдуманного текста

Дополнительно обработаны **10 настоящих инструментальных отрывков GuitarSet**,
длительностью 22–29 секунд: два исполнителя × пять стилей. Это не десять полных
песен с пением. Подробные результаты:
[guitarset-results.json](guitarset-results.json).

| Показатель | Фактический результат |
|---|---:|
| Общая длительность | 241,35 с |
| Совпадение аккорда по высотным классам и басу, с весом по времени | 43,55% |
| Совпадение трезвучной основы без баса и верхних надстроек | 65,41% |
| Смены, сопоставленные с эталоном в пределах ±0,5 с | 43 из 50 |
| Число предсказанных смен | 66 |
| Precision / recall / F1 смен | 65,15% / 86,00% / 74,14% |
| Средняя абсолютная ошибка 43 совпавших смен | 0,114 с |
| Неожиданные строки/слова текста | 0 на всех 10 отрывках |
| Общее время обработки | 158,23 с |
| Время одного отрывка | 11,20–22,70 с |
| Максимальный измеренный RSS | 1569,36 МиБ |

Метрики нормализуют энгармонические названия и обозначения баса через
`mir_eval==0.8.2`; например, `C` эквивалентен `C:maj/1`, а `C/E` — `C:maj/3`.
Сравнение полных аккордов учитывает расширения и пропущенные тоны, а не только
мажор/минор. Упрощённая метрика трезвучия не является точностью полного аккорда.
Ошибка смен относится только к найденным совпадениям; пропуски и лишние смены
отражены отдельно.

Источник: [GuitarSet v1.1.0](https://zenodo.org/records/3371780), CC-BY-4.0.
Использована performed-разметка, описанная авторами как полуавтоматическая
с ручной проверкой. Её границы/root также опираются на исходный chord sheet;
в этой работе разметка дополнительно человеком не проверялась.
Известные файлы со смещениями из
[исправления авторов](https://github.com/marl/GuitarSet/issues/5)
в выборку не включены.

## Как воспроизвести

Сначала установите backend и веса по [инструкции](../../backend/README.md).
Из корня проекта, после установки зависимостей backend:

```bash
backend/.venv/bin/python -m pip install -r scripts/requirements-evaluation.txt
python3 scripts/download_guitarset_subset.py
backend/.venv/bin/python scripts/evaluate_guitarset.py \
  --fixtures backend/data/evaluation/guitarset \
  --work backend/data/evaluation/guitarset-results \
  --output backend/data/evaluation/guitarset-report.json
```

Загрузчик проверяет официальные контрольные суммы двух архивов и выбирает
те же десять файлов. Размер исходных архивов — около 700 МБ. Файлы аудио,
полные эталонные тексты и веса остаются в игнорируемом каталоге `backend/data`,
а не включаются в исходники приложения.

Полный английский набор через HTTP:

```bash
cd backend
.venv/bin/python -m freetune_analysis.download_evaluation --count 20
.venv/bin/python -m freetune_analysis.benchmark \
  data/evaluation/jamendo/manifest.json --output data/evaluation/report.json
```

## Ограничения доказательств

Точность автоматического разбора пока не позволяет обещать готовые безошибочные
тексты и аккорды. Ошибки зависят от голоса, манеры пения, аранжировки и гармонии;
редактор и предупреждения — необходимая часть сценария.

Физического Android и iPhone для проверки не было. Скорость на телефоне,
системный выбор документов, аппаратное декодирование всех вариантов MP3/WAV/M4A,
точность повторов на разных устройствах и поведение при системном завершении
приложения во время проигрывания требуют отдельной проверки. Сборка и smoke
Android-приложения остановлены по запросу пользователя; unit-тесты не выдаются
за такую проверку. Windows/Docker/CUDA инструкции предоставлены, но измерения
выполнены на Linux CPU.
