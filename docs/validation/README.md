# Проверка текущей реализации разбора аудио

Текущая ветка: `feature/audio-song-analysis`. APK не собирается. Публичный сервер
не развёрнут, физический Android недоступен. Проверки с заменённым нативным
проигрывателем подтверждают поведение кода, а не работу MediaPlayer на телефоне.

## Сохранённая история и воспроизводимость

- [Исходная версия v1](baseline-v1.md): EN20, две языковые пробы и десять
  инструментальных отрывков, со ссылками на исходные численные отчёты.
- [Checkpoint отвергнутого v2](quality-v2-recovery-status.md) и
  [сохранённые числа](quality-v2-observed-checkpoint.json): результаты прежнего
  эксперимента. Его незакоммиченные исходники/сырые результаты были потеряны
  при сбое рабочей среды. Кандидат не принят из-за регрессий; эти числа не
  являются результатами восстановленного кода.
- [Зафиксированный план v3](quality-v3-plan.json): что было известно до новых
  запусков, правила сравнения и пять новых инструментальных контролей.
- [Диагностика настоящей модели](quality-v3-native-diagnosis.json): два прежних
  проблемных отрывка × small/turbo × два/четыре потока. Turbo добавляет слово
  на инструментальных записях даже через старый обработчик; small оставляет
  текст пустым. Это ограничение модели, не основание для фильтра по названию
  песни или удаления конкретной фразы.
- [Источники UK/RU v3](slavic-corpus-v3-sources.json): пять полных вокальных
  записей каждого языка, права, авторы, ревизии первичных страниц и хеши.
  Это явно новый восстановленный набор, а не объявление прежних потерянных
  восьми записей теми же самыми файлами.
- [Версии Python-зависимостей](quality-v3-python-environment.txt).

## Автоматические проверки

Для общего сервиса проверяются реальные SQLite и TCP-запросы: отдельные
установки, недоступность чужих заданий, идемпотентность, ограничения до чтения
multipart, отмена до/после публикации задания, потерянный ответ загрузки,
очередь, перезапуск, время хранения, повтор неудачного удаления и сохранение
занятого места. Старая серверная база мигрирует транзакционно; второй процесс
не меняет базу уже работающего сервера. Более новая схема отвергается.

Клиентские проверки охватывают автоматическую регистрацию, неизменность
владельца задания, повтор того же GET при временных сбоях, `Retry-After`,
сохранение прежнего частного подключения и отмену именно текущего поколения.
Интеграция SQLite проверяет старые песни, ручные исправления, альтернативный
автоматический результат, конфликт ревизий, backup v1/v2 и привязку аудио
по SHA-256. Частные и автоматические ключи доступа в backup не попадают.

Команды из корня проекта:

```bash
npx tsc --noEmit
npm test -- --runInBand
npm run test:sqlite
(cd backend && .venv/bin/python -m pytest -q tests)
node scripts/configure_analysis_service.cjs --check
```

Последняя команда с поставляемым пустым URL **должна завершаться ошибкой**:
готовность обычного сценария нельзя подтвердить до развёртывания настоящего
общего HTTPS-сервиса. Она не запускает APK и не выполняет оплату.

## Что считается доказательством качества

Распознавание получает только полный аудиофайл и выбранный язык. Эталонные
тексты читаются отдельно, после инференса, исключительно для подсчёта ошибок.
Основной WER совместим с исторической лексической нормализацией. Отдельный
marker-aware WER сохраняет `…` как ошибку; NFKC превращает многоточие в точки,
поэтому старую метрику нельзя называть такой, которая всегда считала маркер
отдельным словом.

Парное сравнение обработчиков использует один и тот же выход модели. Это
отделяет эффект кода от смены весов, случайности декодирования и числа потоков.
Для времён приводятся покрытие точными словами и ошибки на общих совпадениях
с эталоном. Строка без времён слов остаётся в текстовом выравнивании, но не
создаёт выдуманные интервалы. Меньшее покрытие нельзя выдавать за улучшение
точности всех слов.

Все 20 EN-записей уже использовались в предыдущих экспериментах: теперь это
регрессионный набор, не независимый итоговый holdout. Новый инструментальный
holdout — пять отрывков игрока 05 GuitarSet, выбранных до инференса. UK/RU
содержит по две отложенные записи, но членство восьми записей в потерянном v2
неизвестно, поэтому независимость от прежних опытов не заявляется.

Ни у одной из десяти UK/RU записей нет проверенной человеком разметки именно
этого исполнения. WER/временная точность для них — `null`; опубликованные стихи
не подставляются вместо эталона. Человеческих эталонов гармонии полных вокальных
песен также нет. Отдельные аккордовые оценки GuitarSet не заменяют такую проверку.

## Восстановление записей

```bash
cd backend
.venv/bin/python -m freetune_analysis.download_evaluation --count 20
cd ..
python scripts/download_slavic_corpus.py
python scripts/download_guitarset_subset.py --help
```

Аудио, веса и ограниченные лицензией полные эталонные тексты находятся в
игнорируемом `backend/data`. Они не становятся ресурсами приложения. Новые
примеры разрешено распространять только с соответствующей лицензией записи,
авторами и указанием добавленной визуализации/перекодирования.

## Оставшиеся ограничения

Не проверены: физический Android, OEM-декодеры/системный выбор документов,
реальные прерывания приложения ОС, аппаратная точность перемотки/A–B,
публичная инфраструктура, Docker/CUDA и Windows во время выполнения.
Linux CPU и модульные проверки не заменяют эти пункты. Новую независимую
вокальную проверку с человеческими UK/RU текстами, временными границами и
аккордами ещё необходимо выполнить.
