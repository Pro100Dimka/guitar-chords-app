# Историческая проверка исходной версии v1

Результаты этого документа относятся к исходной реализации до восстановленных
изменений v3. Они сохранены для сравнения; не выдавайте старое число тестов,
демонстрации и измерения за проверку текущего состояния ветки. Актуальная
сводка находится в [README.md](README.md).

Этот отчёт разделяет проверку кода, измерения реальных моделей на Linux и
проверку Android. Эмулятор не считается физическим телефоном. Сборка APK
остановлена по отдельному запросу пользователя; готовый APK и проверка
Android-приложения во время выполнения не входят в результат этой работы.

## Проверка приложения и сохранности данных

- TypeScript: `npx tsc --noEmit` — успешно.
- ESLint: `npx eslint . --quiet` — без ошибок.
- Jest: **14 наборов, 110 тестов** — успешно.
- SQLite: `npm run test:sqlite` — успешно на реальной SQLite, включая миграцию
  старых данных и настроек, откат транзакции, дубли, отмену, поздний ответ
  предыдущего задания, прерывание/повтор, сохранение ручных правок,
  конфликт ревизий, резервную копию/восстановление/привязку аудио и удаление.
- Android JVM: **4 проверки правил** — успешно. Они проверяют сигнатуры файлов,
  безопасные пути, границы повтора и замену повреждённой локальной копии.
  Это не проверка MediaPlayer на устройстве.
- Backend: **33 целевых теста** — успешно, включая контракт, отмену, повторы,
  реальное декодирование, сохранение частичного результата и остановку
  дочернего процесса после принудительного завершения сервера.

Тесты интерфейса проверяют использование фактической позиции проигрывателя,
паузу/перемотку, сохранение ревизии и изменения границ строки. Они используют
управляемый нативный мост, а не доказывают точность MediaPlayer на телефоне.
Гонка отмены импорта с быстрым повтором сначала воспроизведена падающим тестом,
затем устранена: завершённые hash-файлы больше не удаляются из старого callback.

Отдельно **32 из 32 настоящих результатов моделей** прошли именно функцию
`validateSongAnalysis` из приложения, без копирования или ослабления валидатора:
20 EN, 2 RU/UK и 10 инструментальных отрывков. Проверены 698 интервалов строк,
5417 интервалов слов, 2119 интервалов аккордов и соответствие SHA-256 исходников.
Максимальное расхождение длительности результата с исходным файлом через
FFprobe — **0,052109 с** при допуске клиента 0,5 с. Это проверка контракта и шкалы
времени, а не точности слов или нативного проигрывания.
[Данные проверки](client-contract-results.json).

## Полные песни: текст и время слов

Фактические измерения находятся в
[jamendo-small-results.json](jamendo-small-results.json): **20 из 20 полных
английских записей** завершили реальный разбор. В наборе есть разные голоса,
поп, рок, рэп и другие аранжировки, вступления и инструментальные промежутки.

| Показатель | Фактический результат |
|---|---:|
| Длительность всех 20 исходных записей | 4333,04 с — 72 мин 13 с |
| Суммарное время циклов HTTP + анализа | 1266,88 с — 21 мин 7 с |
| Время одного полного разбора, минимум / медиана / максимум | 33,82 / 60,61 / 125,87 с |
| Время анализа / длительность исходников | 0,292 |
| Пиковый RSS | 1810,87 МиБ — 1,77 ГиБ |
| WER по всем словам | **36,19% — 2257 ошибок на 6237 слов** |
| WER отдельных песен | 14,35–77,44% |
| Средняя ошибка начала / конца совпавшего слова | 0,380 / 0,351 с |
| Покрытие временной оценки точными совпадениями | **3853 из 5693 слов — 67,68%** |

Источник: [JamendoLyrics](https://huggingface.co/datasets/jamendolyrics/jamendolyrics)
и [Jam-ALT](https://huggingface.co/datasets/jamendolyrics/jam-alt).
При распознавании используется только аудио. Человеческие тексты Jam-ALT
и временные метки JamendoLyrics подаются только в последующую оценку.
Новая человеческая разметка в этой работе не создавалась.

WER — число замен, удалений и вставок, делённое на число слов эталона.
Маркеры `…` учитываются как ошибки. Средняя ошибка начала/конца слова считается
только для точно совпавших при выравнивании слов; её нельзя распространять
на пропущенные и неправильно распознанные слова. Поэтому рядом сохраняется
число совпадений и количество слов эталона. Человеческих аккордовых эталонов
у этой выборки нет: поле `chordAccuracy` намеренно равно `null`.

Каждая запись прошла настоящий цикл HTTP upload → job → polling → result,
с проверкой SHA-256/ключа задания и очисткой файлов. Измерения выполнены
на общем Linux x86-64 CPU (доступно 9 логических CPU AMD EPYC 9V74,
распознавание INT8 в 4 потока), одновременно с разработкой. `wallSeconds` включает
цикл HTTP; `elapsedSeconds` — обработку worker. Пик RSS включает worker
и его дочерние процессы, но не HTTP-сервер, файловый кеш ОС или GPU VRAM.
Это не производительность Android, Windows-компьютера пользователя или GPU.

### Выбор размера модели

Две реальные модели сравнены на **одном и том же файле Cortéz**, с одинаковым
Whisper DTW и анализатором аккордов. Условия — Linux CPU, INT8, 4 потока.

| Показатель | Whisper small | Whisper large-v3-turbo |
|---|---:|---:|
| Установленные веса + конфигурация | 486 214 945 байт | 1 621 668 118 байт |
| WER на этой песне | 17,98% | 13,76% |
| Полный HTTP-цикл | 49,242 с | 96,949 с |
| Пиковый RSS | 1803,95 МиБ | 2500,66 МиБ |
| Точные совпадения для временной оценки | 295 из 355 слов | 310 из 355 слов |
| Ошибка начала / конца на этих совпадениях | 0,237 / 0,173 с | 0,505 / 0,428 с |

Подмножества совпавших слов различаются, поэтому две средние ошибки времени
не являются парным сравнением одних и тех же слов. Один пример также
не доказывает улучшение качества turbo на всём наборе или на RU/UK.
`small` оставлен вариантом по умолчанию: меньшая загрузка и память, примерно
вдвое меньшее время в этом сравнении и проверка на 20 полных песнях.
`turbo` доступен явно через установку весов и переменную окружения;
пользователь может выбрать его, если важнее снижение ошибок текста.
Модели по-прежнему работают на своём компьютере, без платного сервиса.

Ранний запуск turbo был прерван нехваткой памяти при одновременной Android-сборке.
Он исключён из оценок качества; в таблице приведён только последующий
успешный полный запуск. [Данные сравнения](whisper-comparison.json).

### Демонстрационная песня

**Cortéz — Feel (Stripped)**, исходная длительность 240,562 с: 46 строк текста,
350 интервалов слов и 78 интервалов аккордов. Реальный HTTP-цикл занял
49,242 с, worker — 47,593 с, пик RSS — 1803,95 МиБ. WER — **17,98%**
(64 ошибки на 356 слов эталона). Эти показатели относятся к этой песне,
а не заменяют средний результат на всей выборке.

Источник — [Jamendo, track 1481500](https://www.jamendo.com/track/1481500/feel-stripped).
Поле `copyright` исходного MP3 прямо указывает
[CC BY 3.0](https://creativecommons.org/licenses/by/3.0/), поле `artist` — Cortéz.
MP4-демонстрация содержит первые 75 секунд с исходным темпом и автоматической
разметкой; это визуализация результата backend, **не запись экрана Android**.
Звук перекодирован в AAC. HTML-файл содержит полный неизменённый MP3 и тот же
результат; SHA-256 встроенного аудио проверен. Эталонные слова в демонстрацию
не подставлялись. Скрипты `create_audio_demo.py` и `create_analysis_video.py`
позволяют воспроизвести оба файла.

Готовый MP4 проверен через FFprobe и декодирование кадра: 75,000 с, 960×540,
8 fps, H.264/AAC, оба потока начинаются с 0. Корреляция звука с тем же
фрагментом оригинала — 0,99945. Видеокадры проверены визуально. В HTML проверены
совпадение встроенного JSON с реальным ответом, контрольная сумма MP3 и
синтаксис JavaScript; запуск HTML в браузере здесь не проверен, поскольку
среда не разрешила необходимые браузеру Unix-сокеты.

## Украинская и русская записи

Дополнительно полный HTTP-сценарий пройден на двух настоящих вокальных записях:

| Запись | Язык | Длительность | Разбор | Пик RSS | Результат |
|---|---|---:|---:|---:|---|
| «Реве та стогне Дніпр широкий», Pavlo Hunka / Albert Kravolt, 2010 | uk | 125,240 с | 32,759 с | 1309,04 МиБ | 6 строк, 54 интервала аккордов |
| «Калинка», Albert Janpolski / Victor Records, 1910 | ru | 123,525 с | 66,687 с | 1803,22 МиБ | 2 строки, 6 интервалов аккордов |

Это **проверка выполнения анализа на выбранном языке, не проверка качества
RU/UK**. В классическом украинском вокале и шумной исторической русской записи
есть существенные ошибки и пропуски. Общие опубликованные тексты существуют,
но порядок слов, куплетов и повторов для этих конкретных исполнений человеком
не сверялся. Поэтому WER, ошибки времени и точность аккордов здесь равны `null`.
Нельзя переносить английские оценки качества на украинский и русский.

Источники: [украинская запись и CC BY-SA 4.0](https://commons.wikimedia.org/wiki/File:Mykola_Lysenko_-_The_Dnieper_River_Rages.flac),
[русская запись и отметка PD-US-record-expired](https://commons.wikimedia.org/wiki/File:Калинка._Альберт_Янпольский_(IA_78_kalinka_albert-janpolski_gbia0420126a).flac).
FLAC преобразованы целиком в mono PCM16 WAV без вырезания вступлений,
удаления пауз или изменения темпа. Аудио не включено в git.
Воспроизведение загрузки: `python3 scripts/download_slavic_smoke.py`.
Подробности: [slavic-smoke-results.json](slavic-smoke-results.json).

Первый русский запуск обнаружил конкретный дефект: распознаватель вернул
служебную подпись `СПОКОЙНАЯ МЕЛОДИЯ` как строку песни на 23,94–26,74 с.
Добавлен узкий фильтр известных подписей в верхнем регистре или оформлении
субтитров; обычные строки со словом «музыка» сохраняются. Пропуск подписи
вызывает явное предупреждение `non_lyric_caption_omitted`. Повторный реальный
разбор русского файла подтвердил её удаление. Это не классификатор наличия
вокала и не гарантия отсутствия других галлюцинаций. Прослушивание этих секунд
при этой проверке не выполнено: доступный runtime не принимал аудио.

Фильтр применяется к окончательным строкам. Аудит всех сохранённых EN20
подтвердил, что он **не изменяет ни один из двадцати результатов**; повторять
тяжёлое распознавание ради этого не потребовалось.
[Аудит исправления](caption-filter-audit.json).

Метрики нормализуют энгармонические названия и обозначения баса через
`mir_eval==0.8.2`; например, `C` эквивалентен `C:maj/1`, а `C/E` — `C:maj/3`.
Сравнение полных аккордов учитывает расширения и пропущенные тоны, а не только
мажор/минор. Упрощённая метрика трезвучия не является точностью полного аккорда.
Ошибка смен относится только к найденным совпадениям; пропуски и лишние смены
отражены отдельно.

Источник: [GuitarSet v1.1.0](https://zenodo.org/records/3371780), CC-BY-4.0.
Использована performed-разметка, описанная авторами как полуавтоматическая
с ручной проверкой. Её границы/root также опираются на исходный chord sheet;
в этой работе разметка дополнительно человеком не проверялась.
Известные файлы со смещениями из
[исправления авторов](https://github.com/marl/GuitarSet/issues/5)
в выборку не включены.

## Как воспроизвести

Сначала установите backend и веса по [инструкции](../../backend/README.md).
Из корня проекта, после установки зависимостей backend:

```bash
backend/.venv/bin/python -m pip install -r scripts/requirements-evaluation.txt
python3 scripts/download_guitarset_subset.py
backend/.venv/bin/python scripts/evaluate_guitarset.py \
  --fixtures backend/data/evaluation/guitarset \
  --work backend/data/evaluation/guitarset-results \
  --output backend/data/evaluation/guitarset-report.json
```

Загрузчик проверяет официальные контрольные суммы двух архивов и выбирает
те же десять файлов. Размер исходных архивов — около 700 МБ. Файлы аудио,
полные эталонные тексты и веса остаются в игнорируемом каталоге `backend/data`,
а не включаются в исходники приложения.

Полный английский набор через HTTP:

```bash
cd backend
.venv/bin/python -m freetune_analysis.download_evaluation --count 20
.venv/bin/python -m freetune_analysis.benchmark \
  data/evaluation/jamendo/manifest.json --output data/evaluation/report.json
```

Для RU/UK загрузчик создаёт и provenance `sources.json`, и готовый
`manifest.json` без выдуманных эталонов. Из корня проекта:

```bash
python3 scripts/download_slavic_smoke.py
cd backend
.venv/bin/python -m freetune_analysis.benchmark \
  data/evaluation/slavic/manifest.json --output data/evaluation/slavic-results/report.json
```

Проверка результатов настоящим TypeScript-валидатором, из корня проекта:

```bash
node scripts/validate_analysis_results.cjs \
  --manifest backend/data/evaluation/jamendo/manifest.json \
  --results backend/data/evaluation \
  --output backend/data/evaluation/client-contract.json
```

Путь `--results` должен быть каталогом, в котором benchmark сохранил
`<id>.analysis.json`. Для отдельной проверки GuitarSet доступны параметры
`--guitarset-results` и `--guitarset-fixtures`.

## Ограничения доказательств

Точность автоматического разбора пока не позволяет обещать готовые безошибочные
тексты и аккорды. Ошибки зависят от голоса, манеры пения, аранжировки и гармонии;
редактор и предупреждения — необходимая часть сценария.

Физического Android и iPhone для проверки не было. Скорость на телефоне,
системный выбор документов, аппаратное декодирование всех вариантов MP3/WAV/M4A,
точность повторов на разных устройствах и поведение при системном завершении
приложения во время проигрывания требуют отдельной проверки. Сборка и smoke
Android-приложения остановлены по запросу пользователя; unit-тесты не выдаются
за такую проверку. Windows/Docker/CUDA инструкции предоставлены, но измерения
выполнены на Linux CPU.
