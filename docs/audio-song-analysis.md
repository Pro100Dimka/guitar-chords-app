# Разбор песни из аудио в FreeTune

Функция добавляет в существующую библиотеку исходную запись, распознанный текст,
аккорды и их интервалы. Это реальный анализ выбранного файла: приложение не ищет
другую версию песни и не подставляет текст или аккорды из каталога.

## Готовность и обычный сценарий

Выбрана обработка на сервере разработчика с адресом, записанным в конфигурацию
приложения перед выпуском. В обычном интерфейсе нет ввода IP и токена; пользователь
не устанавливает Python или модели. Сервер работает на бесплатных моделях без
платного API, рекламы и обязательной подписки.

**Публичный сервер ещё не развёрнут.** В `src/config/analysis-service.json`
намеренно оставлен пустой `url`. Приложение сообщает, что общий сервис недоступен,
и не разрешает отправку. Наличие готового backend и скрытых частных настроек
не означает, что обычный пользователь уже может получить автоматический разбор.
Хостинг, домен и платные ресурсы в этой работе не подключались. APK не собирался.

После развёртывания разработчиком и проверки реального HTTPS-адреса сценарий такой:

1. **Библиотека → Добавить аудио**: MP3, WAV или M4A. Приложение проверяет
   содержимое, длительность и свободное место, затем сохраняет устойчивую копию
   в закрытом каталоге. Локальный предел — 256 МиБ и 30 минут.
2. В **Разборе песни** выбрать украинский, русский, английский или автоопределение.
   Приложение показывает фактический адрес, готовность, лимиты и правила хранения.
3. Подтвердить отправку **полного файла** показанному сервису. Анонимный ключ
   установки выдаётся автоматически; аккаунт, адрес или токен от пользователя
   не требуются. Сам запрос готовности аудио не отправляет.
4. Следить за очередью и этапами; при необходимости отменить. При временной
   ошибке опрос повторяет то же задание с учётом `Retry-After`. Дневной лимит,
   перегрузка и ошибка связи объясняются в интерфейсе.
5. Прослушать оригинал, проверить текст/аккорды, исправить разметку. Сохранённый
   результат, оригинал и правки доступны без сервера после перезапуска приложения.

В общей конфигурации по умолчанию: один работающий анализатор, восемь активных
заданий всего, до двух на установку, 20 попыток в сутки на установку и 60 на
сетевой адрес. Одновременно принимаются два файла, не более одного на установку.
Загруженное и декодированное аудио удаляется после завершения или отмены;
результат доступен до 24 часов. Неудачное удаление сохраняет занятое место в учёте
и повторяется, вместо ложного подтверждения освобождения ресурса.

Доступ к заданиям привязан к отдельному ключу установки. Ключи исключены из
резервных копий; сервер хранит их хеши. При истечении доступа следующий явный
запуск создаёт новую установку. Владелец уже начатого задания не меняется.
При потере сети телефон сохраняет локальную отмену; доставка отмены серверу
зависит от связи, а серверные сроки обработки и удаления остаются ограниченными.

### Подключение разработчиком

Установка моделей, запуск backend, TLS, ограничения контейнера и HTTP-контракт
описаны в [backend/README.md](../backend/README.md). После запуска собственного
общего сервиса разработчик выполняет из корня репозитория:

```bash
node scripts/configure_analysis_service.cjs --url https://YOUR-ACTUAL-SERVICE
node scripts/configure_analysis_service.cjs --check
```

Это команды разработчика, не шаги пользователя. Скрипт проверяет настоящий
HTTPS `/health`, готовность моделей, режим общего сервиса, авторизацию установок,
лимиты и политику удаления **до** записи адреса. Пустая конфигурация не проходит
`--check`; несуществующий адрес не считается развёрнутым сервисом.

Режим **Дополнительно → Свой сервер** сохранён для прежних установок и разработки.
Старый адрес/токен не удаляются при переходе на общий сервис. Для частной сети
допускается HTTP с явным предупреждением, для общего сервиса требуется HTTPS.

## Проигрывание и исправления

Кнопка воспроизведения запускает **именно импортированную запись**. Подсветка
читает фактическую позицию Android MediaPlayer. Пауза не продвигает текст,
перемотка сразу выбирает соответствующие интервалы. Вступление и паузы
между строками остаются пустыми. Каждому аккорду не назначается условный такт.

- Нажмите на строку или аккорд, чтобы перейти к его времени. Удержание аккорда
  открывает существующие гитарные аппликатуры.
- Поставьте **A**, перейдите к концу нужного фрагмента и поставьте **B**.
  Повтор выполняется нативным проигрывателем. «Снять повтор» очищает границы.
- В режиме редактирования меняйте отдельные слова, строки, аккорды, начало
  и конец интервалов. Время задаётся в секундах или `м:сс` от начала оригинала.
  Соседние интервалы автоматически не растягиваются.
- При переписывании строки её старые тайминги слов удаляются: новое написание
  нельзя честно совместить с прежними словами. Сохраняется явный интервал
  всей строки. Если новые границы строки исключают прежние слова, приложение
  отдельно подтверждает удаление их таймингов.
- Подчёркнутые фрагменты и `…` требуют проверки по записи. Строки без надёжного
  времени слов имеют явную подпись о приблизительном интервале строки;
  равномерное распределение времени по словам не выполняется. При сбое одного
  анализатора полезный результат второго сохраняется с объяснением.
- Позиция воспроизведения сохраняется при выходе и периодически во время
  занятия. При переходе в фон звук ставится на паузу; возврат читает состояние
  проигрывателя, а не предполагает, сколько времени прошло.

В интерфейсе различаются **аккорд записи**, **транспонированная партия** и
**форма пальцев с каподастром**. Например, для звучащего C и каподастра на
втором ладу предлагается форма B♭. Изменение транспонирования меняет
показанную партию; высота исходного аудио не меняется, о чём показано сообщение.
Распознавание исходного боя, перебора и табулатуры не выполняется.

## Почему выбран сервер

Реализован общий backend для развёртывания разработчиком; частный режим также
сохранён. Он применяет multilingual **Whisper small** через
faster-whisper/CTranslate2 для пения, DTW по вниманию Whisper для времени слов
и **LV-Chordia** — ансамбль пяти CQT-сетей с HMM — для музыкальной гармонии.
Все анализаторы получают одну исходную запись с неизменным нулём времени.
Перед распознаванием не вырезаются и не склеиваются участки тишины.

Whisper small требует около 486 МБ загрузки с конфигурацией; пять моделей
аккордов — около 28 МБ. Дополнительно поддерживается Whisper large-v3-turbo
(около 1,62 ГБ). Реальная серверная обработка требует существенно больше
памяти, чем размер файлов весов. Измерения и ограничения приведены в
[отчёте проверки](validation/README.md), а лицензии кода **и весов**,
фиксированные ревизии, контрольные суммы и причины выбора — в
[MODEL_LICENSES.md](../backend/MODEL_LICENSES.md).

На физическом Android обработка этими моделями в этой работе не измерялась.
Поэтому качество, скорость и расход памяти локального варианта на телефоне
не объявляются доказанными. Выбранный вариант переносит тяжёлую обработку в отдельный процесс сервера,
сохраняет отзывчивость интерфейса и оставляет повторные занятия автономными.
Результат распознавания пения и гармонии требует проверки человеком.

| Вариант | Качество и ресурсы | Расходы / доступность |
|---|---|---|
| Модели на Android | Реальных измерений пения на физическом телефоне нет; серверные числа сюда не переносятся | Нет загрузки песни на сервер; остаются загрузка весов, память, процессор и батарея телефона. Не реализован как проверенная замена |
| Сервер, Whisper small | Исторический EN20 WER 36,19%, до 1810,87 МиБ RSS; свежие парные измерения в отчёте проверки. Около 486 МБ файлов ASR + 28 МБ аккордовых весов | Пользовательский сценарий бесплатный; процессор, память, диск и исходящий трафик обеспечивает разработчик. Тариф/сервер не приобретались |
| Сервер, Whisper turbo | Около 1,62 ГБ файлов ASR; предыдущий кандидат требовал около 2,5 ГиБ RSS и провалил инструментальные проверки. По умолчанию не включён | Больший расход ресурсов; меньший средний WER сам по себе не оправдывает ложные слова и ухудшение синхронизации |

Исторические числа не являются обещанием скорости текущего выпуска.
Сравнение исходной версии и исправлений, ухудшения по отдельным песням,
временное покрытие и недоступные проверки находятся в
[docs/validation](validation/README.md). Публичная инфраструктура и доступность
обычного сценария остаются отдельным незавершённым этапом.

## Хранение и совместимость

Изменения SQLite добавляют `song_audio` и `audio_analysis_jobs` к текущей схеме.
Существующие песни, исполнители и настройки не пересоздаются. Запись связана
с обычным `songs.id`, поэтому остаётся в текущей библиотеке, поиске и избранном.
Аудио хранится в закрытом каталоге приложения `FreeTuneAudio`, имя определяется
SHA-256 содержимого. Повторный импорт того же файла открывает ту же песню.

Ручная версия и новый автоматический результат хранятся раздельно. Повторный
разбор не заменяет ручные исправления без действия **Использовать новый
результат** и подтверждения. Редактор проверяет ревизию перед сохранением;
поздний ответ отменённого задания не может заменить результат нового.

При перезапуске незавершённое задание становится «Прервано» с возможностью
повторить. Исходный файл остаётся на телефоне. Нативное копирование очищает
временные `.part`; не привязанные к базе полные копии старше суток очищаются
при следующем запуске, до открытия библиотеки. Это исключает удаление файла,
который быстрый повтор импорта уже использует.

**Резервная копия JSON включает разметку, правки, альтернативный результат,
настройки и отпечаток аудио, но не сам аудиофайл.** Версия формата повышена до 2;
чтение старых копий версии 1 сохранено. Лимит резервной копии — 50 МБ,
текстового импорта — 5 МБ. При переносе храните оригинальные MP3/WAV/M4A отдельно.
После восстановления нажмите **Найти исходное аудио** и выберите тот же файл:
совпадение SHA-256 обязательно. Другая версия песни, перекодированный файл или
запись с обрезанным вступлением не привязываются к старым таймингам.

Удаление приложения удаляет его закрытую копию аудио. Удаление аудиопесни
удаляет её разметку и копию в приложении; исходный файл у выбранного поставщика
документов остаётся. Backend очищает загруженные и декодированные файлы
по завершении/отмене, а состояние задания хранит ограниченное время.
Подробности повторов и хранения описаны в [контракте](../backend/README.md#http-contract).

Импорт и воспроизведение оригинала реализованы для Android. На других
платформах сохраняются прежние функции; импортированную через резервную копию
разметку можно читать и редактировать, но новый Android-модуль не вызывается.
Сборка iOS и физические устройства в эту проверку не входят.

## Проверка без сборки APK

Нужны Node.js 22 и зависимости проекта.
Из корня репозитория:

```bash
npm ci
npx tsc --noEmit
npm test -- --runInBand
npm run test:sqlite
```

По запросу пользователя APK не собирается. Тесты нативного моста с заменённым
проигрывателем не доказывают воспроизведение, перемотку и повтор на телефоне.
Ветка сохраняет прежнюю конфигурацию Android; рабочая библиотека не пересоздаётся.

Целевые проверки покрывают миграцию старой базы, транзакционное восстановление,
дубли, сохранение правок, конфликт ревизий, отмену/повтор, поздний ответ старого
задания, границы общей шкалы времени, перемотку, паузу и поведение редактора.
Фактический объём проверки реальными аудиозаписями и устройствами, включая
оставшиеся пробелы, указан в [отчёте](validation/README.md).
